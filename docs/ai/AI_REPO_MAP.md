# EduOS — Repo Map for AI Work

Only what AI tasks need. Verified on branch `feature/ai-platform-v1` (base: billing commit `09f5a5e`). If a path has moved, fix this file in the same change.

## Stack in one paragraph
.NET 9 minimal-API microservices behind a YARP gateway and nginx. React + Vite + TypeScript frontend. One PostgreSQL 16 database with a schema per service (`auth_db`, `school_db`, `student_db`, `teacher_db`, `parent_db`, `suite`, `billing`). Data access is EF Core plus raw SQL; there is no Prisma. Migrations are idempotent SQL files applied by the owning service at start. Docker Compose for everything.

## Authentication, RBAC, tenancy (shared library — reuse, do not copy)
| Path | What it is |
|---|---|
| `services/shared/EduOS.ServiceAuth/EduOSAuthenticationExtensions.cs` | JWT validation, policies, per-request session check against auth-service, `UseEduOSAuthorization(prefix, anonymousPaths…)`. |
| `services/shared/EduOS.ServiceAuth/TenantContext.cs` | `TenantContext(SchoolId, UserId, Role)`, `IsPlatform`, `http.GetTenant()`. The only trusted source of school id. |
| `services/shared/EduOS.ServiceAuth/TenantScopeMiddleware.cs` | Forces `schoolId` in query and JSON body to the token's school; rejects mismatches. Anonymous paths are exact matches. |
| `services/shared/EduOS.ServiceAuth/PermissionAccess.cs` | Route → permission map used by gateway and services. **Unknown resources are denied**; an `ai` entry must be added. |
| `services/shared/EduOS.ServiceAuth/EduOSPolicies.cs` | Role names, policy names, platform tenant id `…e005`. |
| `services/auth-service/Program.cs` | Login, refresh, token issue, startup migrations, `/api/internal/session/{id}`. |
| `services/auth-service/Iam.cs` | `Permit`, `Scope`, `Check`, `Audit`, advisory lock, permission seeding, templates, school boundary. |
| `services/auth-service/PermissionCatalogue.json` | Permission keys and default roles. Generated by `scripts/build-iam-catalog.mjs`; edit the script, then regenerate. |
| `services/auth-service/PlatformAdmin.cs` | Super Admin school management (`/api/platform/*`). |

Access tokens carry `permission` claims, `data_scope` (`platform`, `school`, `teacher`, `parent`, `student`) and `token_version`. Services forward the user's bearer token; there is no separate service credential.

## Running the real-database tests
Never against the core database or the default compose project. Use an isolated project and throwaway credentials from the shell, not `.env`:
1. Export `COMPOSE_PROJECT_NAME=eduos-ai-validation`, `AI_DB_PASSWORD` and `AI_DB_APP_PASSWORD` (random values).
2. Start only the database, with a small override file that publishes `127.0.0.1:55432:5432` and adds a normal bridge network to `ai-db` (the project network is internal): `docker compose -f docker-compose.yml -f <override> up -d --wait ai-db`.
3. Export `AI_TEST_DB_OWNER` (user `eduos_ai_owner`) and `AI_TEST_DB_RUNTIME` (user `ai_app`) as connection strings to that port, then run `dotnet test services/ai-service.tests`.
4. Stop it with `docker compose --profile ai -f docker-compose.yml -f <override> down` (the profile is needed, or the container is left running).
